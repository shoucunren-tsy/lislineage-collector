# 采集工作流

一位学者走一遍。多位学者分别建文件夹，不要合并表格。

## 第 0 步 · 身份卡

先确定「这个人是谁」，再开始搜。

0. **查重**：到 lislineage.com 搜姓名，已经有页面的学者跳过、不采。快速判断即可（一两分钟），拿不准就问维护者。
1. 从机构官网师资页拿到：姓名、院系、职称、研究方向、邮箱（若有）。
2. 记下所有姓名写法：中文全名、英文/拼音、曾用名、常见误写。
3. 查 ORCID 与 OpenAlex，确认作者 ID。
4. 写下同名风险：同机构同名、同领域同名、常见姓名。

产物：`profile.csv` 首行、`sources.csv` 前几条、`rejects.csv` 的同名记录。

> 身份没定住就开始批量收论文，后面返工成本最高。

## 第 1 步 · 来源普查

按下面的清单过一遍，找到的就登记：

- 机构师资页 / 个人主页
- 学院新闻、研究生院导师介绍
- ORCID
- OpenAlex 作者页
- 知网/万方作者页
- 期刊编委页
- 学会理事/专委会名单
- 公众号（机构号、学会号、个人号）
- 会议官网、讲座海报页
- 学位论文库（本人学位论文）
- 出版社作者页、豆瓣读书（仅作二手线索）

产物：`sources.csv` + `audit.csv` 每个渠道一行。

## 第 2 步 · 中文论文

推荐顺序：

1. **期刊官网目录**：按年卷期逐期翻，最可靠，能看到完整作者与页码。
2. **知网**：作者检索，注意同名与机构过滤；被引可见则记 verified。
3. **万方/维普**：补充题录；被引常被 WAF 拦截，记 blocked。
4. **国家哲学社会科学文献中心**：补题录，通常无被引。
5. **机构成果页 / 年度科研统计**：补遗漏。

每条要拿到：标题、完整作者序列、期刊、年、卷、期、页、DOI（若有）。

判定归属：

- 作者列表里必须出现本学者（含变体名）。
- 只有「致谢」「导师」出现的不算。
- 会议综述、书评、访谈、媒体报道不算论文，转 `activities.csv` 或 `rejects.csv`。

产物：`papers_cn.csv`。

## 第 3 步 · 外文论文

推荐顺序：

1. **OpenAlex**：`https://api.openalex.org/works?filter=author.id:<ID>&per-page=200`，用 cursor 翻页。
2. **DOI 反查**：拿到 DOI 后访问 `https://doi.org/<DOI>` 核对题录。
3. **Crossref API**：按作者名 + 机构交叉验证。
4. **会议官网**：OpenAlex 收录不全的会议论文。
5. **Google Scholar / 必应学术**：只作线索，需回到出版页确认。

注意：

- OpenAlex 的作者消歧会串人，逐篇看标题、合作者、机构。
- 预印本与正式发表版是同一成果时，保留正式版，预印本进 notes 或 `venue_type=preprint` 单独登记并说明。
- 非英文外文（日、韩）也进 `papers_intl.csv`，`language` 标清楚。

产物：`papers_intl.csv`。

## 第 4 步 · 被引

见 `references/sourcing-rules.md` 第五节。要点：

- 来源页有就记，没有就 `unknown`；
- 被拦截 `blocked`；
- 0 必须有页面明确显示；
- 未知绝不填 0。

## 第 5 步 · 履历

按时间顺序拼：

1. 官方简介 / CV（最权威）
2. 学院师资页（常含教育背景）
3. 学位论文库（本人硕博论文，含导师与年份）
4. 任职公告、干部任免公示
5. 校友报道、访谈（二手，作补充）

每段都要有一手来源和原句。查不到起止年就留空，不要倒推。

常见陷阱：

- 「1997 年获博士学位」≠「1993–1997 攻读博士」；
- 「2018 年受聘」≠「2018 年至今」；
- 兼职、双聘要单独成行，不要并入主职；
- 行政职务与专业技术职务分开写。

产物：`career.csv`。

## 第 6 步 · 活动动态

用 `WebSearch` 跨渠道搜，至少覆盖：

| 渠道 | 检索式示例 |
|---|---|
| 机构新闻 | `"姓名" site:<单位域名>` |
| 学院动态 | `"姓名" 讲座`、`"姓名" 学术报告` |
| 公众号 | `"姓名" 微信公众号`、`"姓名" 会议 综述` |
| 学会 | `"姓名" 中国图书馆学会`、`"姓名" 情报学 专委会` |
| 会议 | `"姓名" 年会 报告`、`"姓名" 论坛 主旨` |
| 获奖 | `"姓名" 获奖`、`"姓名" 优秀成果` |
| 评审 | `"姓名" 评审专家`、`"姓名" 项目验收` |
| 悼念 | `"姓名" 悼念`、`"姓名" 逝世` |

规则：

- 同一条活动被多家报道，只登记最原始的一手来源。
- 日期只确定到月就写 `YYYY-MM`。
- 活动标题照抄，不改写。
- 公众号文章记 `account_name`、`article_title`、`article_url`。

产物：`activities.csv`。

## 第 7 步 · 关系与著作

关系：

- 师承：导师页、学位论文致谢、官方简介「师从」表述。
- 合著：作者序列 + 长期合作关系。
- 同事：同部门、共同项目、共同机构的明确表述。
- 只有「同单位」不算同事。

著作：

- 版权页、出版社书目页、图书馆 OPAC、国家图书馆联合目录。
- 记责任方式（独著/主编/参编/章节）。
- 专著与书章拆分要写清，避免重复计数。

产物：`relations.csv`、`books.csv`。

## 第 8 步 · 检索闭合

逐渠道填 `audit.csv`：

- 有没有翻到最后一页；
- 返回数与唯一数是否一致；
- 渠道报告的总数是否对得上；
- 被拦截的写清现象（403 / 验证码 / 需登录 / 超时）。

零结果也要留一行，写「检索式无结果」。

## 第 9 步 · 自查与交付

1. 跑 `python scripts/validate_package.py <批次目录>`，错误清零。
2. 写 `report.md`：覆盖等级、来源清单、排除判断、**边界与缺口**、复现步骤。
3. 填 `manifest.json` 的 `coverage`、`boundaries`、`gaps`。
4. 跑 `python scripts/pack.py <批次目录>` 生成哈希。
5. **每位学者的文件夹单独压成一个 zip** 交给维护者，zip 根就是该学者文件夹。

### 检索止损

为一条事实（一本书的 ISBN、一个出版日期、一个被引数）检索约 5–10 分钟仍无结果，就停：不再换词硬搜、不再换渠道轮询。该字段留空或记 `unknown`/`pending`，在报告「边界与缺口」里点名，继续下一条。

例外：身份没定住（同名未排除、单位对不上）不是止损范围——人没对上就整个停下来。

## 检索式模板

```
"<中文名>" (site:<机构域名> OR site:<学院域名>)
"<中文名>" ("讲座" OR "报告" OR "论坛" OR "年会")
"<中文名>" ("获" OR "奖" OR "荣誉")
"<英文名>" ("author" OR "coauthor") site:openalex.org
"<英文名>" ("conference" OR "proceedings" OR "workshop")
```

检索式要写进 `audit.csv.query`，方便复现。

## 时间预估（供派活参考）

| 维度 | 单学者参考耗时 |
|---|---|
| 身份与来源普查 | 1–2 小时 |
| 中文论文（含逐期核） | 3–8 小时，取决于产量 |
| 外文论文 | 2–4 小时 |
| 履历 | 2–4 小时 |
| 活动动态 | 2–5 小时 |
| 关系/著作 | 1–3 小时 |
| 自查与报告 | 1–2 小时 |

产量大、同名多的学者时间会翻倍。不要把「一天一位」当默认预期。
