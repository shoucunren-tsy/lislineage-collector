# 判定事故清单

以下都是真实踩过的坑，来自 LIS LINEAGE 历次学者入库。做判定前逐条对照。

## 1. 同名不同人

**现象**：检索到大量同名作者，分布在文学、民族学、体育、网络口碑等完全不同的领域。

**判定**：机构、方向、合作者网络都对不上 → 不是本人。

**处置**：全部进 `rejects.csv`，`reason=同名不同人`，写明「研究方向不符」或「机构不符」。

**注意**：不要因为「名字一样 + 年份接近」就收；也不要因为「方向差一点」就全排除，先看单位。

## 2. 导师署名误挂

**现象**：某条记录里本学者只出现在「指导教师」位置，不是作者。

**判定**：不是论文作者。

**处置**：进 `rejects.csv`，`reason=导师署名误挂`；若该指导关系本身有价值，另在 `relations.csv` 登记师承边。

## 3. 媒体稿、导语、书评

**现象**：报纸报道、公众号导语、书评、会议综述被数据库当成「文献」。

**判定**：不是学术论文。

**处置**：有价值的活动转 `activities.csv`；纯报道进 `rejects.csv`，`reason=媒体稿非论文`。

## 4. 专著与书章重复计算

**现象**：一部专著和它的某一章分别出现在题录里，被当成两项成果。

**判定**：同一成果的两种粒度。

**处置**：专著进 `books.csv`；若章节是独立署名论文，可进 `papers_intl.csv` 并标 `book_chapter`，同时在两处 notes 写明「与 B00X 为同一著作，不重复计数」。

## 5. 连载文章

**现象**：同一组文章分六期连载，标题相同或近似。

**判定**：按实际刊期分别登记，不能合并成一篇，也不能把六期算成六篇独立研究成果。

**处置**：每期一行，notes 写「《组名》连载之N，共6篇」；报告里说明合并口径。

## 6. 聚合页数字不能当计数

**现象**：百度学术作者页显示「论文 178 篇」，逐条实取只有 153 篇；部分条目点进去是空壳。

**判定**：聚合页总数不可作为收录数，也不可作为被引依据。

**处置**：按实际可核条目登记；`boundaries` 写「聚合页称 178，实取 153，未宣称穷尽」。被引为 0 的聚合显示不作数。

## 7. 万方 WAF 与「0 引用」陷阱

**现象**：批量访问万方作者页返回 403 或空白壳，脚本把空结果记成 0。

**判定**：这是访问受限，不是零被引。

**处置**：`cited_status=blocked`，`cited` 留空，`notes` 写「万方 WAF 403」。绝不允许写 0。

## 8. 403 页面不是原文

**现象**：入口返回 403，但有人把 HTTP 状态写成「已核原文」。

**判定**：403 只证明「存在一个受限入口」，不证明内容。

**处置**：受限入口在 `sources.csv` 记 `notes=403 受限`；结论只能引用成功取得的正文、快照或正常浏览器可见内容。

## 9. 受聘事件延伸成「至今」

**现象**：2018 年受聘某研究院研究员，简介直接写「2018 年至今任研究员」。

**判定**：受聘公告只证明受聘事实。后续报道若提到聘期结束，更不能延伸。

**处置**：`start=2018`，`end` 留空，notes 写「受聘事件；是否在任未载」。

## 10. 按学制倒推入学年

**现象**：官方只写「1997 年获博士学位」，采集人补成「1993–1997 攻读博士」。

**判定**：入学年是推断，不是事实。

**处置**：只写 `end=1997`，`start` 留空，notes 写「起止年未载」。

## 11. 学位门类靠猜

**现象**：只知专业，不知授何学位（管理学/文学）。

**判定**：不写。

**处置**：`degree_or_role=博士`，门类留空或 notes 注明「学位门类未载」。

## 12. 专栏/专刊页面作者标错

**现象**：期刊专刊「荐读」页面把两篇文章署成某知名学者，实际作者是另外两位。

**判定**：荐读人 ≠ 作者。

**处置**：回到目次页或 PDF 首页核对作者；错误页面进 `rejects.csv`，`reason=作者列表无本人`。

## 13. 会议论文与期刊版重复

**现象**：同一研究先发会议、后发期刊。

**判定**：两版都真实存在，但不是两项独立研究。

**处置**：两条都登记，notes 互相标注「与 P00Y 为同一研究的会议/期刊版」；统计时由维护者决定口径，采集人不要私自删。

## 14. 预印本

**现象**：arXiv/SSRN 预印本与正式发表版并存。

**判定**：正式版优先。

**处置**：正式版正常登记；预印本若保留，`venue_type=preprint` 并在 notes 写「正式版见 P00X」。

## 15. 「多所著名大学」不是终点

**现象**：官方简介只写「曾在多所著名大学访学/任教」。

**判定**：这是概括，不是履历。

**处置**：继续查三方来源：本人 CV、对方机构新闻、下线页面的搜索索引快照、当年报道。查到一所写一所，查不到就留缺口。

## 16. 兼职与主职混写

**现象**：把「兼任某中心研究员」写进主职，时间线看起来像换过单位。

**判定**：兼职单独成行。

**处置**：`degree_or_role` 写「兼任研究员」，notes 标「兼职」。

## 17. 日期只有年月

**现象**：报道写「2021 年 3 月」，采集人补成「2021-03-01」。

**判定**：编日。

**处置**：写 `2021-03`。只有年就写 `2021`。

## 18. 一条记录挂多个来源

**现象**：同一篇论文从知网、万方、OpenAlex 三处都看到，建了三行。

**判定**：重复。

**处置**：一行，`source_id` 选最可靠的一手来源；其余在 notes 写「另见 S00X」。若不同来源信息冲突，保留冲突说明。

## 19. 站内 ID 乱取

**现象**：新学者 ID 用 `zhangbin_nju`、`binzhang`、`zhangbin2` 等变体，或把 ID 塞在导出末位导致姓名单位串位。

**判定**：ID 必须稳定、唯一、全小写。

**处置**：入库前由维护者分配 `scholar_id`，采集人不得自造；文件夹名与所有表字段统一。

## 20. 用「查不到」当「没有」

**现象**：某渠道返回空，直接结论「该学者没有这类成果」。

**判定**：渠道空 ≠ 事实不存在。

**处置**：`unknown`；report 的边界写「某渠道无返回，未作否定判断」。

## 21. 只查一个搜索引擎

**现象**：只用百度/必应搜一遍就交。

**判定**：覆盖不足。

**处置**：至少覆盖机构站、学术库、公众号、会议/学会四类渠道；每个渠道进 `audit.csv`。

## 22. 报告里写「已全部收齐」

**现象**：报告结尾写「本学者资料已全部收齐」。

**判定**：无法证明，且会误导维护者。

**处置**：改成「已覆盖 X、Y、Z 渠道，边界如下」。校验器会拦截绝对化表述（否定语境除外）。

---

## 快速判定表

| 遇到 | 去处 |
|---|---|
| 名字对、方向对、机构对 | 正式表 |
| 名字对、方向不符 | rejects：同名不同人 |
| 只在导师/致谢位置 | rejects + 可能的 relations |
| 报道/书评/导语 | activities 或 rejects |
| 专著里的章节 | books 或 papers_intl（标章节），不双算 |
| 会议版 + 期刊版 | 两条 + 互相标注 |
| 预印本 + 正式版 | 正式版为主，预印本标注 |
| 查不到 | unknown，不是 0 |
| 打不开 | blocked，不是 0 |
| 拿不准 | pending，不进正式表 |
