# 来源与证据规则

采集的质量不取决于你找到多少，而取决于**每一条能不能被下一个人复核**。

## 一、来源分级

| 级别 | 判定 | 典型页面 |
|---|---|---|
| 一手 | 由当事人、任职机构、正式出版方发布 | 学院师资页、个人官方主页、ORCID、OpenAlex 原始记录、期刊目录页、DOI 落地页、会议官网、学位论文库、正式公告 |
| 二手 | 转载、聚合、二次加工 | 百科、聚合搜索页、第三方公众号转述、新闻转载、商业数据库摘要页 |

规则：

- `confirmed` 履历必须有一手来源。
- 二手来源可以补充线索，但不能单独把 `candidate` 升为 `confirmed`。
- 公众号文章：若为高校/学会官方号发布活动通知或报道，按一手处理，`source_type=微信公众号`；若是个人号转述，按二手。
- 同一事实有一手和二手时，只登记一手那条，notes 写「另见」二手链路。

## 二、摘录（excerpt）

`excerpt` 是「把 URL 点开，肉眼能看到这句话」的逐字复制。

- 至少 6 个字符，建议 15–60 字。
- 不要概括，不要翻译，不要改写标点。
- 不要只写标题（标题本身不足以证明归属，需要作者列表或上下文）。
- 页面是英文就摘英文原句。
- 一条记录只要一句；多处证据用「；」连接，仍须逐字。

反例：

| 反例 | 问题 |
|---|---|
| `学院官网介绍` | 不是原句 |
| `作者发表了该论文` | 概括，回查不到 |
| `冯惠玲等. 档案记忆观...` | 标题不等于证据，缺作者/期刊信息 |
| `据网络资料` | 无出处 |

正例：

```
冯惠玲，女，1953年生，中国人民大学信息资源管理学院教授，博士生导师。
```

## 三、快照（evidence/）

关键来源要落盘，防止页面消失或改版。

- 文件名：`evidence/<source_id>.<扩展名>`，如 `evidence/S003.html`、`evidence/S007.pdf`、`evidence/S011.png`。
- 优先保存：HTML 原文 > PDF > 截图。截图不能替代文字摘录。
- 浏览器保存时选「网页，仅 HTML」或「单个文件」，不要只存链接。
- 快照不超过 5 MB；超大 PDF 只保存涉及页面并注明页码。
- 只保存公开可访问页面。需要登录的内容不要截图扩散，`source_type` 记为受限并在 notes 说明。
- 快照是部分页面时，notes 写「快照仅含首屏」。

校验器会把 `excerpt` 与快照文本比对；快照不全导致的「找不到」是警告，不是错误，但要在 report.md 说明。

## 四、URL 与访问日期

- 用最终落地页 URL，不用搜索结果页、不用短链、不用带跟踪参数的链接。
- URL 打不开但历史页面存在：记原始 URL，notes 写「已失效，另见 web.archive.org 快照」，并把快照存进 evidence/。
- `accessed_at` 填你实际打开页面的日期，不要统一填截止日。
- 同一 URL 只登记一次；不同栏目分属不同页面时分别登记。

## 五、被引次数

这是最容易出错的地方。**未知不是 0。**

| 情况 | cited | cited_status |
|---|---|---|
| 来源页明确显示「被引 12」 | 12 | verified |
| 聚合页显示数值，未回原始库核对 | 12 | recorded_value |
| 来源页明确显示「被引 0」 | 0 | verified_zero |
| 页面没有被引信息 | 空 | unknown |
| 403 / WAF / 验证码 / 需登录 / 超时 | 空 | blocked |
| 渠道改版查不到该文 | 空 | unknown |

决策顺序：

1. 先看题录来源页本身有没有被引字段。
2. 再看同文在其他库的记录（同 DOI、同题名、同作者年份）。
3. 都没有 → `unknown`，不要估、不要取平均值、不要用「大概」。
4. 被拦截 → `blocked`，在 `cited_source` 写渠道名，`notes` 写拦截现象。

`cited=0` 只允许配 `verified_zero`。校验器会对其他组合直接报错。

中国大陆数据库现状（2026-10）：

- 万方检索页对脚本/批量访问有 WAF，常返回 403 或空壳；不要把它当「0 引用」。
- 国家哲学社会科学文献中心（ncpssd）多数题录不提供被引数。
- OpenAlex 对中文文献覆盖很低，查不到不等于不存在。
- 知网页面需要登录，能看到的计数按 `verified` 记，看不到就不记。

## 六、冲突处理

同一事实出现两个版本时：

1. 两个都保留，不要擅自选一个。
2. 一手优先；同为一时以更新日期更近的为准，并在 notes 写另一说。
3. 学位门类、入学年、职务起止这类容易冲突的字段，只在官方明确时填，否则留空。
4. 冲突未解决时，`career.status=candidate`，不要升 confirmed。

示例：

```
notes: 学院页写「1997年获博士学位」，校友报道写「1998年获博士学位」；暂按学院页记，另一说留存待核。
```

## 七、身份消歧

同名是图情领域的高频事故。判定顺序：

1. 机构 + 研究方向是否一致；
2. 合作者网络是否有交集；
3. 论文主题是否与本人长期方向一致；
4. 邮箱/ORCID/个人主页是否出现；
5. 早期论文的机构是否与履历时间线吻合。

任何一条明显不符 → 进 `rejects.csv`，`reason=同名不同人`。

无法确认但又不能排除 → `status=pending`，不进正式表。

## 八、检索覆盖与闭合

「查过」不算覆盖，**翻到底才算闭合**。

每个渠道记录四个数：

- `total`：渠道报告的总条数（不提供则空）
- `returned`：你实际取回的条数
- `unique_ids`：去重后的唯一标识数
- `last_page`：是否到达最后一页

闭合条件：`last_page=true` 且 `returned=unique_ids` 且（`total` 为空 或 `total=returned`）。

任何一条不满足 → `closure=open` + `note` 写原因。**有 open 的维度不能评 A。**

零结果也要记：`returned=0, unique_ids=0, last_page=true, closure=closed`，note 写「检索式无结果」。这样下一个人知道这里查过了。

## 九、不能推断的事

以下内容没有明确原文就不能写：

- 入学年份（不能按学制倒推）
- 学位门类（不能按专业猜）
- 导师（不能按同单位猜）
- 「至今」的任职（受聘公告只证明受聘，不证明仍在任）
- 获奖等级（不能按名称推）
- 论文作者顺序（不能按常见排序补）
- 期刊是否 CSSCI/核心（以当年目录为准，不按印象）

## 十、禁止

- 编造 URL、DOI、页码、被引、导师、获奖、日期；
- 用聚合页数字冒充原始库；
- 把 403 页面当「没有数据」；
- 删除冲突记录让表好看；
- 把同名作者的文章合并进本学者；
- 宣称「全部收齐 / 穷尽 / 无遗漏」。
